# bay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现本机 Go CLI `bay`：扫描两个默认工程根、SQLite 登记、查询、按状态搬入 `_pm/{incubator,archive,trash}`、输出 `doctor` 巡检报告。

**Architecture:** 单二进制；`internal/model` 定义状态与项目；`internal/config` 读 YAML；`internal/store` 管 SQLite；`internal/paths` 负责状态↔路径与旧目录兼容；`internal/scan` / `move` / `doctor` 为纯逻辑（可单测）；`cmd/bay` 用 Cobra 挂子命令。登记库是唯一真相，磁盘位置由 `set` 驱动。

**Tech Stack:** Go 1.22+；`github.com/spf13/cobra`；`gopkg.in/yaml.v3`；`modernc.org/sqlite`（纯 Go，经 `database/sql`）；标准库 `os`/`path/filepath`/`testing`。

**Spec:** `docs/superpowers/specs/2026-10-29-bay-design.md`

## Global Constraints

- 默认 roots：`~/CursorProjects`、`~/DeepseekProjects`
- 生命周期目录：每根下 `_pm/{incubator,archive,trash}`；新搬动只写入 `_pm/...`
- 主状态仅六值：`idea|active|paused|kept|archived|trash`；辅标记 `purpose_known`
- `trash` 只隔离、不真删；跨 root 搬迁不做
- `scan` 不覆盖已有 `summary`；`user_set_status=true` 时不覆盖 `status`
- 只扫 root 下一层子目录；跳过 `_pm`、点目录、`ignore`
- 旧 `_incubator` / `_archive`：scan 识别；set 不写入旧路径
- 配置：`~/.config/bay/config.yaml`；库：`~/.local/share/bay/ledger.db`
- 退出码：成功 0；取消确认 / 无匹配 / 错误非 0
- 依赖克制：不做 viper、不做 TUI、不做 LLM

package model

import "fmt"

type Status string

const (
	StatusIdea     Status = "idea"
	StatusActive   Status = "active"
	StatusPaused   Status = "paused"
	StatusKept     Status = "kept"
	StatusArchived Status = "archived"
	StatusTrash    Status = "trash"
)

func ParseStatus(s string) (Status, error) {
	st := Status(s)
	if !st.Valid() {
		return "", fmt.Errorf("invalid status %q", s)
	}
	return st, nil
}

func (s Status) Valid() bool {
	switch s {
	case StatusIdea, StatusActive, StatusPaused, StatusKept, StatusArchived, StatusTrash:
		return true
	default:
		return false
	}
}
